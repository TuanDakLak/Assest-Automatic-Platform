# NotebookLM Automation Testing Guide

This guide explains how to test the automated NotebookLM integration engine, which leverages **Playwright** for browser automation and **BullMQ** for background job queue management.

---

## 1. Prerequisites & Environment Setup

Ensure the following system packages and services are running:

1. **Redis Server**:
   Ensure Redis is active (usually launched automatically via `docker-compose.yml` on port `6379`).
2. **Playwright Browsers**:
   Ensure the Chromium binaries are installed in the API package:
   ```bash
   npx playwright install chromium
   ```

3. **Session Authentication (Google Login)**:
   Since Google NotebookLM requires Google Account authentication, the automation is configured to load session state (cookies and local storage) from a file named `session.json` at the root of `apps/api`.
   
   To create this session file:
   - Run a short custom script or login manually using Playwright in headful mode.
   - Run the following code snippet to save state:
     ```javascript
     const { chromium } = require('playwright');
     (async () => {
       const browser = await chromium.launch({ headless: false });
       const context = await browser.newContext();
       const page = await context.newPage();
       await page.goto('https://notebooklm.google/');
       // Wait for you to log in manually...
       await page.waitForTimeout(60000); // 60 seconds to log in
       await context.storageState({ path: 'apps/api/session.json' });
       await browser.close();
     })();
     ```

## 2. API Reference & Verification

Since the automation is backend-only (no UI requirements), you can trigger and monitor jobs directly via HTTP endpoints.

### Step 1: Trigger Slide Generation
Send a `POST` request to `/api/v1/notebooklm/trigger` containing the topic and markdown source generated by the Research Module:

```bash
curl -X POST http://localhost:3001/api/v1/notebooklm/trigger \
  -H "Content-Type: application/json" \
  -d '{
    "topic": "Next.js 15 Server Action Patterns",
    "markdownContent": "# Next.js 15 Server Action Patterns\n\n## 1. Overview\nServer actions provide direct RPC endpoints...\n\n## 2. Core Concepts\n* **Form Actions**: direct binding...\n\n## 3. Glossary\n* **RPC**: Remote Procedure Call"
  }'
```

**Response**:
```json
{
  "jobId": "1",
  "name": "generate-slides",
  "status": "QUEUED",
  "timestamp": 1785687906129
}
```

### Step 2: Query Job Progress and Output
Retrieve the execution state of the queued job from BullMQ:

```bash
curl -X GET http://localhost:3001/api/v1/notebooklm/jobs/1
```

**Response (while processing)**:
```json
{
  "jobId": "1",
  "state": "active",
  "progress": 0,
  "result": null,
  "failedReason": null,
  "timestamp": 1785687906129
}
```

**Response (when complete)**:
```json
{
  "jobId": "1",
  "state": "completed",
  "progress": 100,
  "result": {
    "success": true,
    "downloadedFilePath": "E:\\Individual-Project\\Assest Automation Platform\\apps\\api\\downloads\\next_js_15_server_action_patterns_presentation_1.pptx",
    "topic": "Next.js 15 Server Action Patterns"
  },
  "failedReason": null,
  "timestamp": 1785687906129
}
```

## 3. Architecture & Error Handling

* **Headless Configuration**: Supported by default. To debug visually in headful mode, set `PLAYWRIGHT_HEADLESS=false` in the `.env` file.
* **Parallel Worker Execution**: The BullMQ worker is configured with a concurrency rate of `concurrency: 2`. This allows two browser instances to execute concurrently.
* **Automatic Retries**: If the selector fails (due to slow network indexing or dynamic Google page elements), the engine retries the steps up to **3 times** with exponential backoff before marking the job as failed.
* **Telemetric Logging**: The NestJS logger outputs logs for every browser automation step (navigation, notebook creation, file upload, indexing, and downloading).
